# Octen Console 界面规范与原型转交说明 (Handoff Guide)

本转交包专为后续研发与设计对接准备，整合了最新校准完成的 **92-Token 统一设计体系**、**核心页面交互原型（Overview 与 Broad Search API）** 以及 **关键组件工程规范**。

---

## 一、 转交文件目录清单

- **`README.md`**：本转交说明文档，梳理色彩演进、布局组件核心尺寸及参考边界。
- **`theme-color v1.1.html`**：新版色板可视化浏览器交互页面（包含浅色/暗色实时预览、对齐状态审计、色值一键复制）。
- **`COLOR_SPEC.md`**：完整的设计 Token 参数定义与中英文说明文档。
- **`sample/`**：包含完整交互逻辑的控制台示例工程：
  - 打开 `sample/index.html` 即可直接在浏览器中体验 Overview（全局概览）、Broad Search API（多路搜索调试台）以及 Settings（设置项）的完整交互，包括亮暗模式切换、多语言代码生成、Mock 查询响应、参数表单以及分栏自由拖拽等。
  - **侧边栏聚焦交互**：侧边栏严格聚焦于本次转交的核心模块，仅支持点击跳转 **Overview**、**Broad Search** 和 **Settings**；其余未交付页面在**视觉外观上保持 100% 完整质感（不置灰、不改变透明度与文字色彩）**，仅在鼠标悬停时体现为禁止点击手势（`cursor: not-allowed`）并拦截跳转，确保原型视觉高保真的同时防止误触。

## 二、 色彩系统主要改动说明 (不含代码实现)

在此次主题规范升级中，我们对原有的设计系统进行了深层次的收敛与标准化，重点解决了“暗色对比度层次不足”、“亮色未对齐项目实际值”、“图表/强调色两套维护困难”以及“网格线透明度渲染瑕疵”四大核心问题：

### 1. 暗色中性深度重塑 (Cult UI 4阶极简深色规范)
- **改动背景**：早期暗色模式偏蓝且层级扁平，界面各容器边界模糊，缺乏清晰的立体层次感。
- **改动方向**：全面转向 Cult UI 所倡导的极简纯深灰调阶梯，建立了从底层到顶层的 4 级纯粹灰阶：
  - **外壳底色**：最暗的外层基底，提供沉浸式背景。
  - **工作区与卡片表面**：略微提亮的深色表面，承载主体内容与表单。
  - **交互与浮层**：次高层级，用于输入控件、下拉菜单与浮动弹出框。
  - **高亮卡片与聚焦态**：最顶层微亮表面，呈现选中态与需要强调的容器。
- **效果提升**：暗色不再泛蓝光，文本对比度显著提高，长时间使用更舒适。

### 2. 浅色模式对齐项目真实用色
- **改动背景**：早期样例文档中部分浅色使用了理想化的默认白底或泛用占位色，与前端项目实际运行时的配色存在偏差。
- **改动方向**：完全提取并对齐了项目实际生产中沉淀的灰白与暖白微调阶梯，使浅色模式下的输入框描边、分隔线、主卡片与背景在色板页面与真实页面实现无缝贴合。

### 3. 强调色与图表色向“全天候通用单色板”收敛
- **改动背景**：原设计为浅色和暗色分别定义了 11 组强调色与 13 组图表数据序列色。经深度比对，两套色彩的色相完全一致，明度差异仅在个位数百分比之内，在实际使用中不仅增加了维护成本，还容易造成用户在切换主题时对图表序列认知的混淆。
- **改动方向**：全面收敛为一套**全天候通用单色（Universal Palette）**。通过严谨的感知明度与对比度测算，选取了在浅色纯白背景和暗色深灰表面上均具备优秀辨识度与色彩饱和度的黄金值。
- **单项微调**：将玫瑰强调色（Rose）微调校准为兼具活力与暗底通透感的标准玫红色。

### 4. 暗色图表网格线由透明度统一为固定中性色阶
- **改动背景**：此前暗色图表网格线采用了半透明高光描边。在 HTML5 Canvas 或 SVG 图表渲染时，水平与垂直网格线的交叉点会出现透明度叠加发亮现象，且在不同显示器下抗锯齿容易发虚。
- **改动方向**：将暗色网格线彻底替换为色板中的固定中性色阶（与浮层底色及图表十字准星底色统一）。彻底消除交叉重叠噪点，实现精准的 1 像素物理清晰度。

## 三、双栏布局与自由调节宽度组件规范

在控制台的“Broad Search API”以及后续所有类似的分栏工作台（如 Web Search、Extract、Multimodal Search 等模块）中，中间均配备了**自由调节宽度组件（Split Handle Resizer）**。其核心交互规范与刚性边界参数如下：

### 1. 核心最小宽度约束 (Min-Width Values)
为防止用户在拖拽过程中将任意一侧压缩至内容不可读或表单布局崩溃，系统设定了双向对称的刚性最小安全宽度：
- **左侧面板（参数配置区）最小宽度**：**`400px`**
- **右侧面板（代码预览与响应区）最小宽度**：**`400px`**
- **宽度保护计算机制**：在拖拽过程中，系统会实时监测父级容器的总宽度。当总宽度受限时，左栏的最大允许宽度动态受限于“容器总宽度 - 右栏最小宽度 (400px) - 分割条物理宽度”。无论用户如何移动鼠标，左右两栏的可见宽度永远不会跌破 400px。

### 2. 调节手柄物理规格
- **物理视觉间隙**：手柄在分栏布局中占据 **`6px`** 的物理间隔宽度。
- **隐形交互热区**：为降低鼠标捕捉难度，手柄向左右两侧各延展 **`4px`** 的透明点击热区，使整体有效交互宽度达到 **`14px`**。
- **反馈指示线**：平时保持静默通透；当鼠标悬停（Hover）或处于拖拽激活（Active）状态时，手柄正中心显现一条 **`2px`** 的品牌主色指示线，并同步将全局鼠标光标切换为水平双向调整指针（`col-resize`）。

## 四、 非必要参考内容排除清单 (无需过度移植)

在阅读或迁移转交原型工程时，请注意区分“核心规范”与“原型演示辅助逻辑”。以下内容属于**非必要参考项**，无需在正式项目中强行移植或过度参考：

### 1. 原型代码高亮组件 (Prism / Syntax Highlighting)
- **性质定位**：原型中引入的 Prism 库及其配套高亮包装脚本，仅用于在静态原型环境下渲染演示用的 Python、cURL、JavaScript 示例代码。
- **指导建议**：正式业务系统通常具备统一的代码编辑器或轻量级高亮体系（如 Monaco Editor、Shiki 或项目既有的高亮插件）。开发团队应直接使用现有技术栈的代码组件，无需迁移原型内部的 Prism 依赖和自定义高亮函数。

### 2. Application Getting Started 模块 (新手引导 / 快速上手卡片)
- **性质定位**：Overview 及部分页面中包含的“Application Getting Started”或引导步骤卡片，属于交互说明层面的占位内容与业务流程示意。
- **指导建议**：该模块并非通用控制台基础架构或标准容器组件。在真实工程中，应根据当前阶段的实际业务需求决定是否保留或采用独立的引导弹窗/抽屉呈现。

### 3. 非核心边缘页面的 Mock 数据与占位交互
- **性质定位**：转交工程中除了 **Overview（概览大盘）** 和 **Broad Search API（深度搜索）** 具备完整完备的交互与真实逻辑对应外，侧边栏其他次要或占位页面（如部分实验性 API 子页面）主要用于展现统一的版式骨架。
- **指导建议**：核心参考请聚焦于 Overview 的指标排版与 Broad Search 的双栏工作台规范，其他页面的内部具体字段与数据结构以业务 PRD 为准。

### 4. 样式表中的历史兼容性别名变量
- **性质定位**：样式表中极少数遗留的兼容性别名（例如早期为了兼容 Tailwind 特定配置的别名变量），仅用于保证老代码不报错。
- **指导建议**：新工程研发应全面直接使用规范的语义 Token（如 `--primary`、`--danger`、`--border` 等），无需在正式项目中重复声明冗余的别名映射。

## 五、 推荐使用与接入方式

1. **查阅色板体系**：双击直接在浏览器打开 `theme-color v1.1.html`，切换右上角的主题按钮，查看 92 个 Token 在浅色与暗色下的实际色值与用途。
2. **体验核心交互**：通过任意静态本地服务（或直接使用项目已启动的本地服务）访问 `sample/index.html`，重点测试 Overview 整体卡片层级与 Broad Search API 左右分栏拖拽（感受 400px 最小宽度的吸附与保护手感）。
3. **样式与类名引用**：直接参考 `sample/css/styles.css` 中关于组件语义化类名与布局容器的规范定义。
